# วัตถุดิบ สต็อก และสูตรอาหาร

เริ่มที่ `/inventory` แล้วเลือกสาขา

1. เพิ่มวัตถุดิบ ใช้หน่วยหลักเป็นกรัม มิลลิลิตร หรือชิ้น รองรับทศนิยม 3 ตำแหน่ง
2. รับสินค้าเข้าด้วยจำนวนในหน่วยหลักและต้นทุนรวมเป็นบาท เช่น หมู 1,000 กรัม รวม 180 บาท
3. เปิด “สูตรอาหารและต้นทุน” เลือกเมนู แล้วใส่ปริมาณวัตถุดิบต่อ 1 ที่
4. ออเดอร์ใหม่จาก QR และเคาน์เตอร์จะตัดสต็อกพร้อมบันทึกออเดอร์ เมื่อบันทึกออเดอร์ไม่สำเร็จ การตัดสต็อกจะย้อนกลับด้วย

ชื่อและหน่วยวัตถุดิบรวมถึงสูตรใช้ร่วมกันทั้งองค์กร ส่วนยอด ราคาทุนเฉลี่ย และจุดเตือนแยกตามสาขา ผู้มีสิทธิ์ inventory.manage เฉพาะสาขาจะดูและบันทึกสต็อกได้เฉพาะสาขานั้น ข้อมูลกลางแก้ได้โดยผู้ได้รับสิทธิ์ inventory.manage แบบทุกสาขา

## พฤติกรรมที่กำหนดไว้

- รับเข้า: คำนวณต้นทุนถัวเฉลี่ยตามยอดบวกที่เหลืออยู่และต้นทุนที่รับเข้าใหม่ เก็บต้นทุนต่อหน่วยเป็นสตางค์ทศนิยม 6 ตำแหน่ง ปัดเป็นบาทเมื่อแสดงผล
- ยอดเดิมติดลบหรือไม่มีต้นทุน: ใช้ราคาจากการรับเข้าใหม่เป็นฐานต้นทุน ไม่ใช้มูลค่ายอดติดลบถ่วงราคา
- ของเสีย: ลดจำนวนโดยใช้ราคาทุนเฉลี่ยปัจจุบัน ไม่อนุญาตให้บันทึกของเสียเกินยอดคงเหลือ
- ตรวจนับ: กรอกยอดจริงที่ต้องการให้คงเหลือ ไม่ใช่จำนวนเพิ่ม/ลด และต้องระบุเหตุผล ราคาทุนเฉลี่ยไม่เปลี่ยน เหมาะกับแก้จำนวนที่ลงผิด หากลงต้นทุนรับเข้าผิด ยังไม่มีหน้ากลับรายการต้นทุนโดยเฉพาะ
- ขาย: ตัดตามสูตร ณ เวลาส่งออเดอร์ โดยอนุญาตยอดติดลบเพื่อไม่หยุดการขาย หน้าสต็อกแสดงยอดติดลบให้ผู้ดูแลแก้ไข
- เมนูไม่มีสูตรยังขายได้ แต่ไม่ตัดสต็อกและแสดงว่าข้อมูลต้นทุนยังไม่ครบ สูตรที่มีวัตถุดิบไม่ทราบต้นทุนก็แสดงว่าไม่ครบเช่นกัน
- ประวัติเคลื่อนไหวเก็บจำนวน ยอดหลังรายการ และราคาทุน ณ เวลานั้น การแก้สูตรไม่เปลี่ยนประวัติเดิม ไม่มีการตัดย้อนหลังสำหรับออเดอร์ก่อนสร้างสูตร
- ราคาขายลบต้นทุนวัตถุดิบเป็นส่วนต่างเฉพาะวัตถุดิบ ยังไม่ใช่กำไรสุทธิ
- ปิดใช้งานวัตถุดิบได้เมื่อออกจากทุกสูตรและทุกสาขามียอด 0 แล้ว เปิดใช้ใหม่ได้ ประวัติไม่ถูกลบ
- หน่วยหลักของวัตถุดิบเดิมเปลี่ยนไม่ได้ เพื่อรักษาความถูกต้องของสูตรและประวัติ หากเลือกผิดให้ปิดรายการเดิมแล้วสร้างใหม่

ตอนนี้เป็นยอดคลังรวมต่อสาขา ยังไม่มีหลายจุดเก็บ โอนคลัง ใบสั่งซื้อ หรือการกลับสต็อกอัตโนมัติจากยกเลิกอาหาร/คืนเงิน การเพิ่มกระบวนการเหล่านั้นต้องบันทึก movement เพิ่มโดยใช้นโยบายคืนวัตถุดิบที่ร้านกำหนด

## การตรวจสอบสำหรับผู้พัฒนา

- `npm run test:inventory` ทดสอบจำนวน เงิน ต้นทุน และสิทธิ์สาขา โดยไม่ใช้ฐานข้อมูล
- `npm run test:inventory:db` ทดสอบรับเข้า สูตร ออเดอร์ การส่งซ้ำ การแยกสาขา rollback และการรับเข้าพร้อมกัน ใช้ Neon ที่ตั้งค่าไว้ สถานการณ์หลัก rollback ทั้งหมด และสถานการณ์พร้อมกันใช้ร้านทดสอบ UUID แยกแล้วลบใน finally
- `node tests/inventory-browser-fixture.cjs` สร้างร้านและบัญชีสำหรับทดสอบหน้าจอเท่านั้น รายละเอียดชั่วคราวอยู่ใน node_modules/.cache ไม่ใช่บัญชีร้านจริง
- หลังทดสอบ UI ใช้ `node tests/inventory-browser-fixture.cjs cleanup` เพื่อลบร้านทดสอบและบัญชีนั้น
- `npm run check`, `npm run build` ตรวจ TypeScript และ production build
- Prisma scripts โหลด `.env.local` ตาม Next.js โดยไม่ต้องคัดลอก connection string ใช้ `npm run db:deploy` เพื่อนำ migration ที่ตรวจแล้วขึ้นฐานข้อมูล

ตาราง balance และ movement เปลี่ยนใน transaction ระดับ Serializable ถ้ามีรายการชนกัน server จะขอให้ผู้ใช้ตรวจแล้วส่งอีกครั้ง คีย์รายการเดิมป้องกันการบันทึกซ้ำ การตัดตามสูตรใช้คีย์เฉพาะออเดอร์และวัตถุดิบ และเขียนยอดหลายวัตถุดิบพร้อมกันเพื่อลดรอบเชื่อมต่อ Neon
