# พนักงาน บทบาท และสิทธิ์

## สมัครเจ้าของร้านใหม่

จากหน้า `/login` เลือก **สร้างบัญชีและร้านใหม่** เพื่อเปิด `/register` แล้วกรอกข้อมูลร้าน สาขาแรก ชื่อเจ้าของ อีเมล และ PIN 6 หลักพร้อมยืนยัน ระบบจะสร้างร้านใหม่พร้อมบัญชี Owner และเข้าสู่ Back Office ให้อัตโนมัติ แม้มีร้านอื่นในระบบอยู่แล้ว ข้อมูลร้านใหม่แยกด้วย `organizationId` และอีเมลต้องไม่ซ้ำกับบัญชีที่มีอยู่

การสมัครร้านใหม่ไม่ต้องใช้ `INITIAL_SETUP_TOKEN` ส่วน `/setup` และ `/access/claim` เป็นขั้นตอนตั้งค่าหรือเปิดใช้บัญชีเดิม ซึ่งยังต้องใช้รหัสตั้งค่าครั้งแรกใน production

## เพิ่มบัญชีพนักงาน

เจ้าของร้านจัดการบัญชีที่ `/settings/staff` โดยทำตามลำดับนี้:

1. สร้างบทบาทจากแม่แบบหรือเลือกสิทธิ์เอง
2. เพิ่มพนักงาน ตั้ง PIN ชั่วคราว 6 หลัก และเลือกบทบาท
3. เลือกขอบเขตเป็นทุกสาขาหรือเฉพาะสาขา
4. พนักงานเข้าสู่ระบบด้วยอีเมลและ PIN ชั่วคราว ระบบจะบังคับเปลี่ยน PIN ก่อนเริ่มงาน

## สิทธิ์ที่มีในระบบ

| สิทธิ์ | ขอบเขต | หน้าที่ |
| --- | --- | --- |
| `organization.manage` | องค์กร | ตั้งค่าข้อมูลหลักของร้าน |
| `branch.manage` | องค์กร | เพิ่มและตั้งค่าสาขา |
| `menu.manage` | องค์กร | หมวดหมู่ เมนู ราคา สูตร และจุดผลิต |
| `user.manage` | องค์กร | พนักงาน บทบาท PIN และสิทธิ์ |
| `table.manage` | สาขา | โต๊ะและ QR |
| `pos.use` | สาขา | Counter POS เปิดโต๊ะและรับออเดอร์ |
| `kitchen.view` | สาขา | คิวครัวและบาร์ |
| `service.manage` | สาขา | เรียกพนักงานและคำขอเช็กบิล |
| `payment.manage` | สาขา | บันทึกการรับชำระเงิน |
| `inventory.manage` | สาขา | สต็อก วัตถุดิบ และต้นทุน |
| `printer.manage` | สาขา | เครื่องพิมพ์และงานพิมพ์ |
| `report.view` | สาขา | Dashboard และรายงาน |

สิทธิ์ระดับองค์กรใช้ได้เฉพาะการมอบหมายแบบทุกสาขา ส่วนสิทธิ์ระดับสาขาใช้ได้ทั้งแบบทุกสาขาและแบบเจาะจงสาขา

## พฤติกรรมด้านความปลอดภัย

- เมนูแสดงเฉพาะส่วนที่บัญชีมีสิทธิ์ และทุก page/Server Action ตรวจสิทธิ์ซ้ำฝั่งเซิร์ฟเวอร์
- บัญชีรายสาขาเปิด URL หรือส่ง action ไปยังสาขาอื่นไม่ได้
- การรีเซ็ต PIN และการปิดบัญชีจะยกเลิก session ทุกอุปกรณ์
- PIN ผิดครบ 5 ครั้งจะพักการเข้าสู่ระบบ 15 นาที
- บัญชีและบทบาทใช้ soft disable เพื่อรักษาประวัติ
- บทบาท Owner ถูกล็อก ไม่สามารถแก้ ปิด หรือนำออกจากบัญชีเจ้าของ
- ฐานข้อมูลปฏิเสธ RoleAssignment ซ้ำแบบทุกสาขาและการผูก User, Role หรือ Branch ข้ามองค์กร
